# Snowmass 273 篇首轮生产翻译设计

日期：2026-08-10  
状态：用户已批准执行  
范围：仅处理 `site/data/papers.json` 中 `publication_allowed: true` 的论文

## 1. 目标与硬约束

本系统把获准公开改编的 Snowmass 英文论文转换为可审计、可恢复的简体中文学术译稿。每篇论文依次经历忠实翻译、术语统一、去 AI 口癖、中文自然化/学术化四个逻辑阶段，并分别保存源文件、阶段产物、请求用量、校验结果和最终拼接结果。

以下条件不可绕过：

- 工作队列必须从实时公共清单推导，只接受 `publication_allowed is True`；缺失、`false`、`null` 均阻止。
- 当前首轮预期为 273 篇，但任何实现不得硬编码 273。
- 不得连接、探测或使用受限 SCNet 昆山、四川节点。
- 数字、单位、公式、引用、URL、邮箱、标签和锁定术语不得被润色阶段改变。
- 任一阶段只有在响应状态、结构校验和内容校验全部通过后才能记为完成。
- 运行必须支持关机、休眠、进程退出和网络中断后的精确续做。

## 2. 选定方案（2026-08-10 结构化重构）

采用“双证据源 + BabelDOC 文档 IR + translate-book 状态层 + baoyu refined 文档级审校”的混合方案，不再把递归展开后的原始 LaTeX 当作可直接按字数切分的模型输入。

- 正式 PDF 是版面、页码、图表和已发表可见内容的事实源；BabelDOC/PDFMathTranslate-next 负责把它解析为段落、公式、富文本和版面对象，并在最终阶段回填版面。
- arXiv 源码包是章节、引用、标签、公式源码和完整性比对的第二证据源；注释环境、宏定义和未进入正式 PDF 的内容不得混入翻译队列。
- `translate-book` 负责源指纹、manifest、相邻块只读上下文、术语 v2、按源/术语哈希选择性重译、meta 合并和最终组装。
- `baoyu-translate` 的 `refined + academic` 流程负责每篇论文的整体分析、统一提示、初译、独立批评、修订和终稿一致性检查。
- DeepSeek V4 Flash 只承担有明确输入/输出契约的文本任务；权限、预算、断点、结构恢复和硬校验由本地控制层负责。

该方案保留源码优先的语义证据，但放弃“用正则给整块 LaTeX 堆哨兵”的实现。此前 600 词试译的失败样本已经证明：原始 LaTeX 注释会制造 66 个占位符，URL 正则会跨越 TeX 右花括号，而网络不确定响应不能靠提示词修复。

### 2.1 已安装工具的明确职责

| 能力 | 复用实现 | 本项目不得重复发明的部分 |
| --- | --- | --- |
| PDF 结构与版面 | BabelDOC / PDFMathTranslate-next | 段落、公式、富文本、页面和回排表示 |
| 长文状态与上下文 | `translate-book` | manifest、邻块上下文、run state、选择性重译、meta 合并 |
| 学术精译流程 | `baoyu-translate refined` | `analysis → prompt → draft → critique → revision → translation` |
| 中文学术质量 | `academic-writing-quality` | 论证清晰度、术语和学术语域审查 |
| 去模型腔 | `avoid-ai-writing` / `humanizer-zh-academic` | 仅在忠实度通过后做受限改写 |
| 权限/费用/恢复 | 本仓库控制层 | 273 篇实时权限门、人民币预算、API 事务日志、断点续做 |

## 3. 架构与边界

### 3.1 权限快照

运行开始时生成不可变快照，记录公共清单 SHA-256、选中 `record_id`、许可证、来源 URL 和生成时间。后续所有预处理和翻译命令都消费该快照。快照外记录即使存在本地文件也不能进入队列。

### 3.2 双证据源选择

源码处理器支持 tar+gzip 和单 TeX+gzip 两类 arXiv 包。安全解包拒绝绝对路径、`..` 路径穿越、设备文件以及逃逸根目录的符号链接。主文档按以下证据评分：`\documentclass`、`\begin{document}`、题名、摘要、文件名、引用关系和内容长度。唯一高置信候选自动通过；多候选生成报告并进入人工复核，不静默猜测。

递归展开 `\input` 和 `\include` 仅用于构建源码证据树和完整性索引，限制在解包根目录，检测循环和缺失文件。LaTeX 注释环境、行注释、宏定义、条件编译未选分支以及未出现在正式 PDF 中的重复内容先从正文候选中剥离。标题、摘要、章节、图表标题、正文、引用键和公式源码用于与 PDF IR 对齐；参考文献条目默认保留原文。

### 3.3 BabelDOC 文档 IR

所有记录都从正式 PDF 生成 BabelDOC 中间表示；源码不是其替代品，而是对齐和完整性证据。IR 中每个段落保留页码、版面框、段落类型、公式/富文本对象和稳定 ID。纯数字段、公式对象、图片、图轴、页眉页脚和引用标识不作为自由文本交给模型。低文本密度、乱码、公式密度异常、表格占比高或 PDF/源码对齐失败的页进入复核清单。

BabelDOC 的结构化输出必须先在 3 页无付费解析探针上通过，再进入真实 API 试译。正式运行不把 API key 放入命令行；通过本地适配器从钥匙串读取，并把结构化请求交给现有预算和事务日志层。

### 3.4 类型化保护

保护对象来自 BabelDOC IR 或 LaTeX 解析结果，不再用跨结构的宽泛正则猜测边界。公式、引用、标签、URL、邮箱、代码、单位和普通阿拉伯数字使用不同类型的稳定节点；URL 按 IR 对象或 `\url{...}` 配对花括号解析，禁止用“直到空白”为止的正则。

保护在段落级执行，单个请求不得形成高密度哨兵块。沿用 BabelDOC 的防护思想：当一个段落的结构对象超过 40 个时，不继续堆叠占位符，而是回退到富文本关闭、行/单元级翻译、保留原对象或人工复核。校验器区分“值变化”和“排版变化”：数字值、符号、指数、单位不可变；千分位样式变化单独记录，不伪报为数字丢失。

### 3.5 文档单元与上下文

模型输入以 BabelDOC 段落/标题/图注/表格单元为原子，不以固定词数切割原始 LaTeX。多个低结构密度段落可以组成请求，但不得拆开公式对象、列表项、表格行或图注。请求受三重上限约束：源 token、预计输出 token、结构对象数；任一上限先到即切分。

复用 `translate-book/chunk_context.py` 为每个单元注入约 300 字符的前后只读上下文，并加入当前章节标题、论文级摘要和术语子表；上下文只用于消歧，不得出现在输出。分块结果写入 manifest，源内容、IR 对象和相邻关系均有哈希。

### 3.6 术语层

术语由全局、Frontier、论文三级表组成，优先级由论文到全局。直接复用 `translate-book` glossary v2 的实体 ID、别名、置信度、频次、证据引用、每块相关词和高频 top-N 选择，以及 `merge_meta.py` 的事务式候选合并。模型不得自行改写锁定词；未知高频术语进入候选列表，主控制层解决冲突后才更新术语表。`run_state.py` 根据源哈希和实际使用的术语哈希只重译受影响单元。

### 3.7 每篇论文的 refined 四阶段

`baoyu-translate` 的项目偏好已经锁定为 `zh-CN / refined / academic / 4000-token chunk threshold / 5000 max words`。本项目把它落实为可审计的论文级产物：

1. `01-analysis.md`：先通读论文结构、目的、受众、术语、论证链和易错点，不翻译正文。
2. `02-prompt.md`：生成该论文统一使用的风格、术语、数字/公式/引用和输出契约。
3. `03-draft/`：DeepSeek V4 Flash 按结构单元完成忠实初译；每单元附相邻上下文和相关术语表。
4. `04-terminology/`：确定性检查找出不一致，再由受约束修订处理真实冲突；不得以简单复制冒充术语统一。
5. `05-critique.md`：独立审稿视角逐节核对漏译、误译、逻辑、限定词、术语、中文模型腔和跨块连贯性，不直接改文。
6. `06-revision/`：根据批评逐项修订，并保留问题到修改的映射。
7. `07-final.md`：执行受限去 AI 口癖和中文自然化/学术化；源文事实、数字、单位、公式、引用、链接、专名和锁定术语不得改变。

这里的“翻译 → 术语统一 → 去 AI 口癖 → 中文自然化/学术化”仍是用户规定的逻辑顺序；analysis、critique 是辅助质量闸门，不替代四阶段。确定性规则只负责检测和放行，不能把后两阶段降格为批量 `no-op`。

翻译客户端优先采用可验证结束状态的流式协议，并记录请求 ID、模型、阶段、输入哈希、输出事件、usage 和最后完整事件。`incomplete`、`failed`、缺少终止事件或连接中断不得写入正式阶段文件；明确可重试的传输错误采用有上限退避，状态不明的已计费请求进入 `uncertain` 队列，不盲目重复。

### 3.8 幂等与恢复

每次请求以源哈希、阶段、提示词版本、术语哈希和模型组成 `request_key`。状态先原子写入 `prepared`，成功响应写入独立响应记录，再经校验晋升为 `validated`。只有 `validated` 可以跳过。非空文件不能作为完成证据。

不自动重发状态未知且可能已计费的请求；将其标为 `uncertain`，通过响应 ID/本地日志复核后再决定。明确未送达、429或服务端可重试错误采用指数退避和抖动。运行历史按时间戳保存，不覆盖旧摘要。

## 4. 质量闸门

结构单元级硬校验包括：

- IR 节点 ID、类型、计数和必需顺序一致；
- 数字值、百分数、单位、URL、邮箱和引用标识不丢失、不新增；
- Markdown/LaTeX 保护结构闭合；
- 锁定术语完全符合；
- 响应状态完整且没有达到输出上限；
- 中文正文非空，残留英文只允许专名、缩写和参考文献白名单；
- 输出长度比处于按文本类型配置的合理区间。

论文级校验包括：单元序连续、无重复/缺失、章节和图表标题可追踪、参考文献保留、PDF/源码证据对齐、术语一致性、批评项关闭、所有单元通过硬校验。最终 PDF 还必须逐页渲染并抽检版面。任何硬失败都阻止拼接和发布。

验证器自身必须有反例测试：`2800` 与 `2,800` 只能被标为格式变化；`factor of 2` 译成“两倍”必须按项目数字保留策略明确判定；`\url{...}` 必须由配对解析器得到边界；LaTeX 注释中的结构不得进入正式节点集合。不得为通过测试而把所有数字和 URL 简单排除在校验之外。

## 5. 分批运行与停机条件

先完成全部获准论文的本地权限快照和双证据预处理，不调用 API。随后依次执行：3 页 BabelDOC 无付费结构探针、1 篇代表论文的小额 A/B、10 篇分层样本、50 篇批次、余下论文。

A/B 的 A 路径是现有 LaTeX 文本管线，仅作为基线；B 路径是 BabelDOC IR + translate-book context/glossary/run-state + baoyu refined。只有 B 在数字/公式/引用、结构完整性、跨段连贯性和人工学术质量上均不差于 A，且消除高密度占位符与 URL 边界错误，才允许进入 10 篇试点。

扩大批次前必须满足：权限泄漏为零；数字/公式/引用硬校验通过率 100%；人工抽检忠实度和术语准确度均不低于 95%；格式完整性 100%；重试率低于 5%；实际费用和时间不超过预测 25%。

出现以下任一情况立即停止新请求：任何错误数字/公式/引用、超过 1% 的结构单元触发硬失败、传输不确定率或重试率超过 5%、累计费用超过当前阶段预算、模型或官方价格发生变化、响应模型与声明不一致。

## 6. 运行资源与预算

本机承担解包、BabelDOC 解析、对齐、上下文、术语、校验、审校编排和拼接。DeepSeek V4 Flash 承担必要的模型阶段。初始并发为 1；完成代表论文且传输不确定率为零后，10 篇试点升至 2–4，50 篇最多为 8；只有连续稳定后才考虑 16。不得根据官方连接上限直接设为 32–128。全首轮沿用人民币 100 元硬停机上限，但每个放行阶段还必须有更小的独立预算上限，实际启动前重新读取官方价格。

本地运行期间电脑必须保持开机联网。后台任务使用 `codex-bg` 和原子断点；合盖休眠后任务暂停但不会丢失已验证进度。

## 7. 验收标准

系统完成的证据不是“进程结束”，而是：实时权限快照只含获准记录；每篇有可重现输入；每块有四阶段审计轨迹；所有响应和内容硬校验通过；强制中断测试不会重复已验证请求；论文级拼接无缺块；费用低于批准上限；发布目录仅包含获准论文的验收产物。
