# Snowmass 273 篇首轮生产翻译设计

日期：2026-08-10  
状态：用户已批准执行  
范围：仅处理 `site/data/papers.json` 中 `publication_allowed: true` 的论文

## 1. 目标与硬约束

本系统把获准公开改编的 Snowmass 英文论文转换为可审计、可恢复的简体中文学术译稿。每篇论文依次经历忠实翻译、术语统一、去 AI 口癖、中文自然化/学术化四个逻辑阶段，并分别保存源文件、阶段产物、请求用量、校验结果和最终拼接结果。

以下条件不可绕过：

- 工作队列必须从实时公共清单推导，只接受 `publication_allowed is True`；缺失、`false`、`null` 均阻止。
- 当前首轮预期为 273 篇，但任何实现不得硬编码 273。
- 不得连接、探测或使用受限 SCNet 昆山、四川节点。
- 数字、单位、公式、引用、URL、邮箱、标签和锁定术语不得被润色阶段改变。
- 任一阶段只有在响应状态、结构校验和内容校验全部通过后才能记为完成。
- 运行必须支持关机、休眠、进程退出和网络中断后的精确续做。

## 2. 选定方案

采用“源码优先、PDF 回退、结构保护、语义分块、分阶段门控”的混合方案。

不采用纯 PDF 方案，因为 OCR/版面抽取会混入图轴、页眉、页脚并破坏公式结构。不采用直接 Pandoc 方案，因为实测会丢失标题前置信息和 LaTeX 引用。也不采用把整篇论文交给模型的方案，因为长文输出截断、重试成本和局部返工不可控。

## 3. 架构与边界

### 3.1 权限快照

运行开始时生成不可变快照，记录公共清单 SHA-256、选中 `record_id`、许可证、来源 URL 和生成时间。后续所有预处理和翻译命令都消费该快照。快照外记录即使存在本地文件也不能进入队列。

### 3.2 源文件选择

源码处理器支持 tar+gzip 和单 TeX+gzip 两类 arXiv 包。安全解包拒绝绝对路径、`..` 路径穿越、设备文件以及逃逸根目录的符号链接。主文档按以下证据评分：`\documentclass`、`\begin{document}`、题名、摘要、文件名、引用关系和内容长度。唯一高置信候选自动通过；多候选生成报告并进入人工复核，不静默猜测。

递归展开 `\input` 和 `\include`，限制在解包根目录，检测循环和缺失文件。标题、作者、摘要、章节、图表标题和正文进入翻译源；参考文献条目默认保留原文。

### 3.3 PDF 回退

没有可用源码的记录按页抽取 PDF，保留页码和原始 PDF 引用。页眉、页脚、单独页码和图轴数字只在原图或原页仍被保存时移除。低文本密度、乱码、公式密度异常或表格占比高的页进入复核清单。

### 3.4 结构保护

在分块前把以下对象替换为确定性哨兵：显示/行内数学、引用命令、交叉引用、标签、URL、邮箱、代码、不可翻译标识符和易受破坏的单位表达。映射单独保存，译文必须保持哨兵集合、次数和顺序约束；缺失、重复或新增均为硬失败。

### 3.5 语义分块

默认目标为 1,500 个英文词，允许区间 1,200–1,800。切分优先级依次为章节、段落、句子；不得在公式、列表项、表格行、图注或哨兵内部切分。每块保存前后相邻标题作为只读上下文，但只输出当前块译文。

### 3.6 术语层

术语由全局、Frontier、论文三级表组成，优先级由论文到全局。词条包含源词、规范中文、允许别名、类别、证据和锁定状态。模型不得自行改写锁定词；未知高频术语进入候选列表，不自动覆盖既有译文。

### 3.7 四阶段翻译

1. 忠实翻译始终调用 DeepSeek V4 Flash。
2. 术语统一先运行确定性检查；无冲突时复制前一产物并记录 `no-op`，有冲突时调用模型。
3. 去 AI 口癖先运行规则检查；无命中时复制前一产物并记录 `no-op`，有命中时调用模型。
4. 中文自然化/学术化始终调用模型，并把源文、当前译稿和锁定术语作为约束输入。

所有调用使用 DeepSeek Responses API。客户端必须验证顶层 `status == completed`、响应模型、输出正文和完成事件；`incomplete`、`failed`、截断或缺少终止事件不得写入正式阶段文件。

### 3.8 幂等与恢复

每次请求以源哈希、阶段、提示词版本、术语哈希和模型组成 `request_key`。状态先原子写入 `prepared`，成功响应写入独立响应记录，再经校验晋升为 `validated`。只有 `validated` 可以跳过。非空文件不能作为完成证据。

不自动重发状态未知且可能已计费的请求；将其标为 `uncertain`，通过响应 ID/本地日志复核后再决定。明确未送达、429或服务端可重试错误采用指数退避和抖动。运行历史按时间戳保存，不覆盖旧摘要。

## 4. 质量闸门

块级硬校验包括：

- 哨兵集合、计数和必需顺序一致；
- 数字、百分数、单位、URL、邮箱和引用标识不丢失、不新增；
- Markdown/LaTeX 保护结构闭合；
- 锁定术语完全符合；
- 响应状态完整且没有达到输出上限；
- 中文正文非空，残留英文只允许专名、缩写和参考文献白名单；
- 输出长度比处于按文本类型配置的合理区间。

论文级校验包括：块序连续、无重复/缺失、章节和图表标题可追踪、参考文献保留、所有块通过硬校验。任何硬失败都阻止拼接和发布。

## 5. 分批运行与停机条件

先完成全部273篇的本地预处理，不调用 API。随后执行：1篇源码结构正常的获准论文、10篇分层样本、50篇批次、余下论文。

扩大批次前必须满足：权限泄漏为零；数字/公式/引用硬校验通过率 100%；人工抽检忠实度和术语准确度均不低于 95%；格式完整性 100%；重试率低于 5%；实际费用和时间不超过预测 25%。

出现以下任一情况立即停止新请求：任何错误数字/公式/引用、超过 1% 的块触发硬失败、重试率超过 5%、累计费用超过当前阶段预算、模型或官方价格发生变化、响应模型与声明不一致。

## 6. 运行资源与预算

本机承担解包、解析、分块、术语、校验和拼接。DeepSeek V4 Flash 承担必要的模型阶段。初始并发为 1–2，10篇试点为4，50篇为8；只有连续稳定后才提升到16。全首轮按当前价格设置人民币100元硬停机上限，实际启动前重新读取官方价格。

本地运行期间电脑必须保持开机联网。后台任务使用 `codex-bg` 和原子断点；合盖休眠后任务暂停但不会丢失已验证进度。

## 7. 验收标准

系统完成的证据不是“进程结束”，而是：实时权限快照只含获准记录；每篇有可重现输入；每块有四阶段审计轨迹；所有响应和内容硬校验通过；强制中断测试不会重复已验证请求；论文级拼接无缺块；费用低于批准上限；发布目录仅包含获准论文的验收产物。
