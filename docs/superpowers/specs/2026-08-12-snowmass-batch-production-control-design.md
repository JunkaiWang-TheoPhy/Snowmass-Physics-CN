# Snowmass 批量生产控制面设计

日期：2026-08-12  
状态：用户已批准执行  
范围：仅处理实时公共清单中 `publication_allowed: true` 的论文

## 目标

在现有 BabelDOC、refined 四阶段翻译、回填渲染和发布装订能力之上增加一个可复用的跨论文控制面。它必须解决三个生产瓶颈：费用不能跨进程失控、论文不能靠人工逐篇启动、质量失败不能继续扩散到后续批次。

## 方案比较与选择

1. **追加账本 + 文件锁 + 阶段状态机（采用）**：只用 Python 标准库，在本地持久化项目预算、请求预占/实结和逐篇阶段状态。优点是与现有脚本兼容、断电可恢复、无需服务；代价是只适合单机共享文件系统。
2. SQLite 控制库：事务更强，但会引入迁移、并发连接和人工诊断成本；当前单机批量不需要。
3. 每次进程内重新汇总：改动最少，但进程重启和并行运行可能同时超支，不能满足硬预算。

采用方案 1。现有每篇 `api_cost_ledger.jsonl` 继续作为细粒度审计证据；新的项目账本是所有新请求的唯一跨论文预算裁决者。

## 预算契约

- 命令必须同时接收 `--project-max-cost-rmb` 和 `--stage-max-cost-rmb`；两者必须为有限正数，`0`、负数、NaN 和无穷均非法。
- 每个阶段还必须设置有限正整数 `--stage-max-api-calls`；`0` 不得表示无限请求。跨进程共享账本必须把已结算、状态不明和活动预占请求一并计数，并在下一次付费调用前硬停止。
- 项目上限不得超过用户批准的 `¥1000`。首次创建控制目录后，上限不可提高；后续只能保持或降低。
- 阶段上限不得大于项目上限，且只约束当前 `run_id` 的新增费用。
- 首次建账扫描既有 Snowmass API 账本并记录一次历史基线；此后不重复导入。
- 每次 API 调用前在文件锁内写入保守预占。成功后按 usage 实结；传输状态不明或失败则按保守预占扣费。进程崩溃遗留的预占在下次启动时自动转为保守已花费用。
- 任意进程在项目或阶段预计费用越界时，在发出请求前抛出预算异常；不允许 `0 = 无限预算`。

## 编排状态机

队列从 `site/data/papers.json` 实时推导并生成带清单 SHA-256 的运行快照。支持互斥的 `baseline`、`pilot10`、`batch50`、`remainder` 分层分区和显式记录列表；各阶段默认分别取 1、10、50 和其余允许记录，合并后恰好覆盖权限清单且绝不重复。预置阶段数量只是上限，实际总数永远从权限清单推导。

每篇依次经历：

`queued → prepared → translated → rendered → qc_passed → packaged`

每个状态保存输入/输出哈希和错误摘要。重启时仅复用通过现有脚本哈希检查的状态，不以“文件存在”代替完成。任何 `blocked`、`uncertain`、预算异常或质量硬失败都会停止调度尚未开始的论文。

## 成本效率

- 参考文献正文、图内文字、表内文字和其他已判定旁路块不得进入模型；边界检测必须容忍 PDF 抽取造成的条目碎片和运行页眉。
- 普通结构密集块每请求最多容纳 24 个受保护节点；只有结构协议失败时才缩小到 8 个，避免按 4 个节点机械拆成数十次调用。
- 每个 QC 失败块只允许一次自动付费纠错；第二次仍失败则保留断点并隔离，禁止在同一进程内连续尝试五次。
- 复用已有 `revision_no_actionable_chunk_critique`：论文批评未点名的块保留审计阶段但不调用模型。
- anti-AI 阶段保持独立模型审校；不得用局部标记检测把完整风格审校伪装成确定性完成。
- academic 阶段仍逐块执行，保证自然化/学术化不是空操作。
- 图内文字、表内文字、参考文献、固定页眉和硬对照继续本地透传或确定性替换，不调用模型。
- 先运行 baseline，再运行 10 篇分层样本；根据实测每万源字符费用、重试率和 QC 失败率决定 50 篇放行，禁止直接全量并发。

## 自动质量闭环

翻译阶段沿用数字、单位、公式、引用、URL、保护节点、术语和响应完整性校验；refill 阶段沿用页眉、参考文献顺序、图内文本、表格文本和渲染区域校验；装订阶段沿用权限、禁用误译、封面和可复现收据校验。

控制面汇总每篇的 `paper_status.json`、全部 `chunk_status/*.json` 和 `refill_status.json`，只有以下条件全部满足才晋升：

- 论文及全部块均为 `complete`，不存在 `failed`、`uncertain` 或 QC `ok: false`；
- `publication_qc.ok`、参考文献验证、图/表区域验证全部为真；
- 原始渲染 PDF 保留，装订 PDF 与收据存在且哈希匹配；
- 当前运行的重试/不确定比例不超过阶段门限，且累计费用不超过阶段和项目上限。

每个运行总表还必须固化 API 调用数、输入/缓存/输出 token、每篇费用、每万源字符费用、按当前样本外推的 273 篇总费用，以及机器可读的 `promotion_gate`。任何尚未解决的不确定付费请求、未完成装订、活动预占、文章失败或外推总费用超过项目上限，都会关闭下一阶段放行；不得仅凭进程退出码自动扩大批次。已由操作员显式授权重放且最终成功的请求仍永久保留保守费用和历史歧义计数，但以追加式 `resolve_uncertain` 事件关闭风险，不得冲销费用或改写旧账。

## 分阶段执行

本轮授权总上限为 `¥1000`，但生产启动采用更小放行额度：先复用或完成一篇 baseline，再以累计阶段预算 `¥50` 运行 10 篇试生产。只有自动 QC 全绿且成本预测仍处于项目上限内，后续才允许 `batch50` 和 `remainder`。受限 SCNet 节点始终不在执行路径中。

## 验收

- 旧 runner 和新 runner 均拒绝缺失、零或非法人民币预算。
- 两个并发 guard 不能共同越过同一项目上限；进程重启不能遗忘费用或活动预占。
- 队列仅含实时允许发布记录，当前预期 273 但代码无硬编码。
- 中断后不会重做已验证阶段；任何硬 QC 失败停止后续论文。
- 运行报告给出总费用、阶段费用、每篇状态、token/调用数、失败原因和下一阶段是否可放行。
