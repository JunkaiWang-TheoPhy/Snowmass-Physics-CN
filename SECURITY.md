# Security and privacy reporting

This repository must not contain credentials, private contact details, authorization correspondence, unpublished translation drafts without publication rights, or unredacted evidence attachments.

If you find exposed private data, a credential, or an authorization bypass:

1. Do not open a public issue containing the material.
2. Use GitHub Private Vulnerability Reporting for the repository.
3. Identify the affected path or commit without reproducing the secret or correspondence.
4. If a translation was published without a valid gate, identify only the public paper ID and URL.

The maintainers will first remove public access, then verify scope, rotate affected credentials where necessary, clean caches or history, and record a redacted resolution.

Ordinary metadata corrections and website bugs can use public issues as long as they contain no private information.
